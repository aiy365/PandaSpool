## 1. 这台机器不是你的专属机

台账里的 yby 是**共享机**。选型必须当邻居，不能按「整台 3.6GB 都给我」。

### 1.1 现在真实占用

| 角色 | 状态 | 对你的含义 |
|---|---|---|
| 腾讯云 tat / barad / **云镜 ~73MB** | 常驻，动不了 | 先扣掉约 100MB |
| **Caddy 2.6.2** | 整机唯一 80/443，证书也在这 | **继续共用**，禁止再装 Nginx / 再抢 80/443 |
| PrintPilot 旧看板 `:8765` | 你说推倒 | **停掉卸载**，端口和 `/opt` 腾出来 |
| OpenClaw Gateway | 服务已卸，**磁盘和 nvm 还在** | 曾经 **947MB 打满机器**。以后随时可能再上飞书 Bot |
| Node 22 via **nvm，装在 `/root/.nvm`** | 给 OpenClaw 用的 | 新业务**不要绑这个 nvm**，避免和 Bot 抢同一运行时 |
| 系统 Python 3.11 | patrol 等脚本在用 | 可以留作运维脚本，不要再当主站运行时 |
| Docker / PM2 / Supervisor | **没有，也不要装** | 台账写明无容器 |
| 磁盘 | 70G / 已用 12G | 够用；空气时序不要无上限写 |
| 带宽 | **6 Mbps / 600GB 月** | 视频不能经这台中转 |
| 内存 | 3.6G 总量，卸 OpenClaw 后曾剩 ~2.6G | 新服务硬顶见下 |

### 1.2 内存预算（硬约束）

```text
3.6 GB
 - 内核 + 系统服务 + 云镜等     ≈ 0.7–0.9 GB
 - 给以后的 Bot / 脚本留空      ≈ 1.0 GB   （OpenClaw 教过一次）
 - Caddy                           ≈ 0.05 GB
 - 本系统常驻上限                 ≈ 0.15 GB
 - 余量 / page cache              ≈ 0.5+ GB
```

**本系统两个进程合计 RSS 目标 < 150MB，报警线 200MB。**  
Node 默认堆就爱涨到几百兆；再和 OpenClaw 重逢会重演 2026-08-11 的 OOM。所以 **主站不用 Node 当常驻运行时。**

端口：公网仍只有 22 / 80 / 443。应用只绑 `127.0.0.1`，由现有 Caddy 反代 `3d.bstccc.cn`。不要用 18789。

## 2. 技术栈：按共享机重选（推倒重来）

旧 Python 标准库 HTTP、旧 SQLite、旧 React 看板、旧用户、旧数据路径 —— **全部不要**。新目录、新库、新 systemd、新登录。

### 2.1 选定

| 层 | 选定 | 原因（对着台账） |
|---|---|---|
| 常驻后端 | **Go 单一静态二进制**（`net/http` 或 chi + 同进程 MQTT） | 无运行时；RSS 通常 20–40MB；不碰 `/root/.nvm`；不和以后的 Bot 抢 Node |
| 前端 | **本机编好的静态 SPA**（Vite + React） | 服务器不跑 Node 构建；Caddy 或 Go 只吐 `dist/` |
| 数据库 | **SQLite**（WAL）新文件 `/var/lib/printpilot/app.sqlite3` | 无 PG/Redis；70G 盘够用 |
| 空气时序 | 同库一张窄表，**按小时降采样、默认留 90 天明细** | 防磁盘被 10s 一条写爆 |
| 证书 / 入口 | **现有 Caddy**，改一条 reverse_proxy | 共享入口，不第二套 TLS |
| 进程 | **一个** systemd：`printpilot.service` | web + 拓竹 MQTT + 易微联策略全在一个进程 |
| 运行用户 | 新建低权限 `printpilot`，家目录不可登录 | 和旧的同名用户可重建，不复用旧文件 |
| 传感器上报 | ESP32 **HTTPS POST** 到 `3d.bstccc.cn` | 第一期无 D2、无公网 MQTT 端口 |
| 拓竹 | 本进程内 MQTT，连 `cn.mqtt.bambulab.com` | 你认可的 yby 主路径 |
| 易微联 / 萤石 | 本进程出站 HTTPS | 不经 D2 |
| 构建 | 你电脑交叉编译 `GOOS=linux GOARCH=amd64` | 服务器**不装** Go 工具链、不装 Docker |

不选：

| 候选 | 为什么否 |
|---|---|
| Node 22 + Hono/Fastify 常驻 | 运行时在 root nvm；堆内存不老实；和 OpenClaw 复活冲突 |
| 旧 Python 包上 FastAPI | 你要求推倒；且别再占一份 venv |
| Next.js / SSR | 3.6G 共享机上浪费 |
| Docker | 台账无 Docker，为这个服务去装不划算 |
| Postgres / Redis | 空端口在，但多一个常驻就多一份内存 |

前端可以用 TypeScript。那是开发机的事。服务器上只有：**Caddy + 一个 Go 文件 + 静态目录 + SQLite**。

### 2.2 上线方式（破坏性，按你的「全不要了」）

1. 停 `printpilot-material-dashboard` 和它的 backup timer。  
2. Caddy 改指新端口（例如 `127.0.0.1:8088`）。  
3. 旧 `/opt/printpilot-material-lab`、旧 `/var/lib/printpilot-material-lab` 整包打 tar 扔到 `/var/backups/` 后删除运行引用。  
4. **不导入**旧 13 产品 / 52 颜色。你要的资料以后重新建。  
5. 新登录、新密码。  

台账改完必须回写 `H:\159_75_227_95-SERVER_STATUS.md`。

## 3. 空气检测：先承认测不到什么

| 真实排放 | 家用探头 | 结论 |
|---|---|---|
| UFP 10–100 nm（ABS 主力） | PMS / SPS / SEN 光学下限约 **0.3 µm** | **全部测不到峰**。别写「已测超细颗粒」 |
| 苯乙烯（ABS）法定浓度 | 要 GC/PID，几千上万 | **买不到便宜法定探头** |
| 打完后团聚的细颗粒 | 光学 PM1/2.5/10 | **能测**，而且往往打完才高 |
| 「空气变脏了」相对变化 | 金属氧化物 VOC 指数 | **能测趋势**，不能写成 mg/m³ 达标 |
| 房间是否符合 GB/T 18883 | 光学 PM2.5/10 | **只能对照参考**，不是认证监测 |

所以选型目标不是「实验室级」，是：

1. 仓内：这种料脏不脏、净化器有没有把曲线压下去。  
2. 仓外：房间 PM 对照国标色带，人在不在。  
3. 两边能对比：封箱漏不漏。

### 3.1 探头逐个结论

**颗粒**

| 型号 | 优点 | 致命点 | 本项目 |
|---|---|---|---|
| Plantower PMS5003 | 便宜，出 PM1/2.5/10 | 分档不准（论文里几乎总挤在 0.3–0.5 µm）；风扇在油雾/粉尘里易死；热环境寿命差 | 不作为仓内主力 |
| Sensirion **SPS30** | PM2.5 对照更好、响应快、声称寿命长、自清洁风扇 | PM10 常跟 PM2.5 差不多；同样看不见 UFP | **仓内颗粒首选** |
| Sensirion **SEN55** | 一颗 I2C 同时 PM+温湿+VOC+NOx | **工作温度上限 50°C**；一体机无法拆到隔板两侧 | **只放仓外** |

**气体**

| 型号 | 优点 | 致命点 | 本项目 |
|---|---|---|---|
| SGP30 | 给出「ppb」好看 | 乙醇当量假浓度；算法旧 | 不用 |
| **SGP41** | 对多种溶剂响应优于 BME688；有原始 `SRAW_VOC`；工作约 −20~+55°C | 指数会**自适应基线**，ABS 打一天会「看起来变干净」；**不是苯乙烯计** | **仓内必上，必须存 raw** |
| BME688 | 一颗含温湿 | 对苯、甲苯、己烷等更钝 | 不用 |
| 电化学甲醛 / PMS5003S | 便宜标甲醛 | 交叉干扰大，3D 打印场景当参考都勉强 | 第一期不上 |

社区里有「SGP41 对某次 styrene print 没反应」的个例，也有 Voron 仓用 SGP41 看过滤效果的。当作 **相对脏度**，不要当 ident 苯乙烯。后台用「相对开打前 10 分钟基线的 raw 变化」，不要用 24h VOC Index 当料种指纹。

**温湿度 / 人体**

| 型号 | 用途 |
|---|---|
| SHT40 | 仓内仓外都要。仓内热管理 + 给 SGP41 湿度补偿 |
| LD2410C | **只仓外**。毫米波存在探测，驱动车间净化器 |

SEN55 仓外已经带温湿和 VOC，仓外不必再堆一颗 SGP41，除非以后要看「漏气 VOC」。第一期仓外 VOC 用 SEN55 自带的即可。

### 3.2 最终 BOM（主外从内，一根线）

```text
仓外主板（人、国标、上网）              隔板排线           仓内子板（材料污染）
ESP32-S3
SEN55          ← 房间 PM1/2.5/10 + 温湿 + VOC/NOx
LD2410C        ← 有人 / 距离
WiFi → 3d.bstccc.cn
5V 供电
                                              I2C：SGP41 + SHT40
                                              UART：SPS30
```

| 位置 | 器件 | 约价 | 测什么 |
|---|---|---|---|
| 仓外 | ESP32-S3 | 15 | 主机、HTTPS |
| 仓外 | SEN55 | 80–110 | 房间 PM + 温湿 + VOC 指数（国标对照用 PM） |
| 仓外 | LD2410C | 15 | 人体 → 车间净化器 |
| 仓内 | SPS30 | 80–100 | 封箱 PM（打完团聚、漏箱对比） |
| 仓内 | SGP41 + SHT40 | 25–35 | 料种 VOC 相对变化、仓温仓湿 |
| 线 / 壳 / 塞孔 | | 20 | 少漏气 |

合计大约 **220–300 元**。比两颗 PMS5003 贵，是因为仓内热 + 要长寿命 + 仓外要对国标。

**不要把 SEN55 塞进封箱。** 50°C 上限，ABS 封箱贴边就会超规格。仓内探头装在**隔板仓内侧、远离热床**，不要吊在喷头旁。

### 3.3 固件必须上报的字段

```json
{
  "ts": 1776500000,
  "room": {
    "t_c": 26.1, "rh": 54,
    "pm1": 6, "pm25": 11, "pm10": 18,
    "voc_index": 98, "nox_index": 1,
    "presence": true, "distance_cm": 160
  },
  "enclosure": {
    "t_c": 38.4, "rh": 28,
    "pm1": 42, "pm25": 55, "pm10": 58,
    "voc_index": 210,
    "sraw_voc": 18420
  }
}
```

`sraw_voc` **必存**。料种画像、打印卡片只用 raw 相对基线，VOC Index 仅作实时「脏了」灯。

仓外 PM2.5 滑动 24h 对照 GB/T 18883 的 50 µg/m³，UI 写「参考对照，非认证」。  
仓内不对齐国标达标，只对齐这次打印。

## 4. 和净化器策略怎么咬合

探头是输入，易微联通断是输出。

| 输入 | 输出 |
|---|---|
| （无条件） | 仓内长开净化器 ON |
| A1 云 MQTT 显示打印中，或结束 < 30 min | 仓内打印加强 ON |
| 仓外 `presence` | 车间净化器 ON |
| 仓外 PM2.5 24h 对照超标 | 飞书（第二期），不自动加开第四台 |
| 仓内 `sraw_voc` 相对基线暴涨且料标 PETG | 机台页打「排放异常」 |

补光仍手开。门磁不做。
