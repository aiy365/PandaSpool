### 1.2 透明颜色字段

Bambu Studio 的设备/AMS 材料界面不能可靠表达“透明”。本次曾使用八位值 `#ECEFF400`，Studio 在用户增量文件中保留它，但展开缓存把默认颜色变成空值。因此：

- 不再使用 ARGB 或 RGBA alpha 作为设备端透明语义。
- 新预设使用稳定的六位 RGB 浅色近似值 `#ECEFF4`。
- 这只影响切片器中的视觉标识，不影响模型透明度、材料类型、流量或 G-code。

### 1.3 为什么设备“材料设置”保存无效

Bambu Studio 存在两套不同数据：

1. **切片耗材预设**：位于“准备”页，决定温度、冷却、流量比例和最大体积流量。
2. **打印机/AMS/BMCU 槽位材料类型**：位于“设备”页，用于描述物理槽位和打印时映射。

导入的新预设已经成功出现在本机用户目录，但导入产生的 `.info` 中 `user_id` 为空；即使后续云同步完成，A/P 系列和 Handy 对自定义耗材的槽位同步也长期存在已知限制。因此不要把“设备槽位必须显示 R3D 自定义名称”作为预设可用的验收条件。

稳定使用流程：

1. 在设备/BMCU 槽位中选择 `Generic PETG`；若列表确实提供，也可以选 `Bambu PETG Translucent`。
2. 在“准备”页的项目耗材列表中选择 `R3D PETG 透明 - 均衡验证版 @Bambu Lab A1 0.4 nozzle`。
3. 完成切片后，在发送打印的映射页把项目耗材映射到实际装有 R3D 透明 PETG 的槽位。
4. 以“准备页选中的预设”和切片结果为准，不以设备槽位显示名称判断 G-code 参数。

如果希望尝试云同步，可以在“准备”页打开此耗材预设并执行一次“另存/保存”，等待账号同步完成；但这不能保证 Handy 或 BMCU 设备页会显示自定义名称。

## 2. 纸抽盒 2.9 小时变成 5 小时以上

目标文件：`C:\文件\Downloads\壁挂式纸抽盒120x80x160.3mf`

### 2.1 文件内能确认的事实

`printpilot inspect` 结果：

- 机器：Bambu Lab A1，0.4 mm。
- 工艺：0.20 mm Standard。
- 墙：2 层，约 0.87 mm。
- 顶层：5 层，约 1.0 mm；底层：3 层，约 0.6 mm。
- 填充：15%，Grid。
- 无支撑。
- 文件保存的耗材不是 R3D PETG，而是 `Bambu PLA Basic @BBL A1`，最大体积流量 21 mm³/s。
- 3MF 内没有已经切好的 G-code，因此文件本身不包含当次实际打印的准确预计时间和实际发送参数。

这意味着当前下载文件只能证明“原始项目状态”，不能证明当次打印使用了 R3D 预设、Bambu PETG Translucent 或哪一个设备速度模式。

### 2.2 参数本身不会在打印中途把 2.9 小时变成 5 小时

耗材最大体积流量在切片阶段已经转换为 G-code 速度。打印机收到 G-code 后，不会因为设备槽位从 Generic PETG 改成 R3D 名称，再重新按 6 或 9 mm³/s 解释整份路径。

因此：

- 如果 2.9 小时来自已经完成切片的结果，R3D 预设不会在打印中途自动把时间翻倍。
- `Bambu PETG Translucent` 的 6 mm³/s 会在切片时直接给出更长的预计时间，不应只在实际打印时才出现。
- 自动调平、流量校准等准备动作通常只增加若干分钟，不足以解释约 2 小时差异。

### 2.3 最可能原因排序

1. **打印机处于静音模式（Silent，约 50% 速度）或运行中被调到较低速度档。** 2.9 h 到 5 h 以上的倍率最接近这一类运行时速度倍率，而且手机显示的切片预计时间通常仍按标准速度。
2. **看到的 2.9 h 与实际发送的切片不是同一份。** 例如手机展示模型页/原始 PLA 方案时间，实际发送的是另一份 PETG 切片或云端重切片。
3. **延时摄影或大量停顿。** 可以增加时间，但对这个高而连续的纸抽盒通常不是首要解释。
4. **短层冷却降速。** 模型主体每层路径较长，不太可能让整体接近翻倍；仅顶部小截面可能触发。

### 2.4 下次打印的最小取证

不要再依赖模型页显示时间。保存以下四项即可闭环：

1. 发送前“预览”页的切片总时间。
2. 发送前项目耗材名称和最大体积流量。
3. 开始打印后 A1/Handy 的速度模式截图（Silent/Standard/Sport/Ludicrous）。
4. 打印历史中的开始、完成时间。

如果运行中是 Standard，且实际时间仍比切片预计多 50% 以上，再收集当次实际发送的 3MF（包含切片结果）和打印机日志，不再用下载原始 3MF 代替。

## 4. OpenCode 后续处理图片的低 Token 流程

### 4.1 边界

- 原图已经上传时，不要重复上传，也不要再生成 stage/review/manifest 三件套。
- 只在原 `source_id` 上追加核对后的声明，再标记 `processed`。
- 产品级资料写到产品，不要因为图片包含颜色表就创建库存。
- 只有资料明确写明某颜色参数不同，才使用 `color_variant` 作用域。
- 字段体系是开放的；遇到新指标，建立明确的 `claim_key`，不要压成 `other`。
- 销售页最高线速度不是最大体积流量；回抽、K/PA 和机械性能不直接覆盖切片参数。

### 4.2 查找待处理来源

在服务器项目环境中使用 `LocalStore` 只读查询。检查 `sources.metadata.processing_status == pending_manual_review`，同时读取：

- `id`
- `product_id`
- `kind`
- `title`
- `origin`
- `storage_path`
- `source_organization`
- `region`

不要读取整个数据库或把原图转成 Base64 放进模型上下文。按 source_id 一张一张下载到临时目录并识图。

### 4.3 提取格式

每一项至少保留：

```python
{
    "key": "tensile_strength",
    "value": 41,
    "unit": "MPa",
    "scope": {
        "direction": "XY",
        "test_standard": "图片明确写出时才填"
    },
    "source_location": "图片：耗材特性/拉伸强度",
    "notes": "只记录必要的歧义或适用边界",
    "review_status": "approved"
}
```

范围使用数组，如 `[230, 260]`；不等式使用对象，如 `{"operator": "<", "value": 300}`；复杂板材温度可以保存对象。不要把 `230–260` 自行缩成单点值。

### 4.4 写入接口

写入前先运行完整备份，然后调用：

```python
from printpilot_material_lab.local_store import LocalStore

store = LocalStore()
result = store.process_product_inbox_evidence(
    source_id="待处理UUID",
    claims=claims,
    extracted_text="人工核对后的图片全文摘要",
    approved=True,
)
```

该接口会：

- 用指纹去重声明；
- 保存提取文本到原图同目录的 `extracted.txt`；
- 保留原始 source 身份；
- 把状态改为 `processed`；
- 不创建占位预设、不修改库存。

写入后再次备份，核对 SQLite integrity、sources 数量和 claims 增量。不要直接执行 INSERT/UPDATE SQL。

## 5. 新预设继续校准时的顺序

1. 先按 R3D 建议 60–65 ℃、4–8 h 烘干。
2. 使用新预设的 255 ℃、Glacier 65 ℃打印温度塔或小型透明测试件。
3. 手动校准流量比例；不要因为客服截图是 0.94 就认为每卷、每种颜色永久相同。
4. 手动校准 K/PA，并单独记录，不写死到共享耗材预设。
5. 做最大体积流量测试，确认 9 mm³/s 是否保持透明一致性、层间结合和表面稳定。
6. 透明优先时可把最大体积流量降到官方 6 mm³/s；效率优先且测试通过时保留 9 mm³/s。

## 6. 验收口径

新预设可用的判断是：

- 在“准备”页能选择；
- 能正常切片；
- 预览中的温度、风扇、体积流量符合预期；
- 发送打印时能映射到实际 PETG 槽位；
- 实测校准结果可重复。

设备页或 Handy 是否显示自定义品牌名不作为切片预设可用性的判断，因为那是独立的设备材料类型/同步链路。
