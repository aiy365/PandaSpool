
# PandaSpool 实用主义架构与 BOM (终极开源版)

> **修订说明**：本版本深度采纳了 Codex 提出的“完全本地化、去中心化、公开可复刻”架构思想，正式废弃了对云服务器、公网 DDNS 及单一 MIPS 路由器的强依赖，全面转向 **“本地边缘节点 (Hub) + 分布式传感器 (Air Node)”** 的现代开源物联网标准模型。

---

## 1. 重新定义产品：100% 本地的私有边缘云

PandaSpool 不再是“一个网页 + 一台远端云服务器”，而是一个像 OctoPrint 或 Home Assistant 一样，**必须部署在打印机同局域网内的边缘计算中枢**。
项目解耦为四个公开、可替换的纯本地模块：
1. **PandaSpool Hub（核心中枢）**：承载 Web UI、数据库、本地 MQTT Broker、自动化规则引擎、摄像头解包及分发。
2. **PandaSpool Core（工艺引擎）**：机器/材料/喷嘴 → 耗材参数与 Profile 规则映射。
3. **PandaSpool Air（环境节点）**：ESP32 采集车间与封箱环境数据（完全摒弃自研固件，全面拥抱 ESPHome）。
4. **PandaSpool Remote（可选插件）**：只有在用户主动需要时，才配置 Tailscale / WireGuard 进行公网穿透访问。

**核心底线**：断网可用，所有数据绝对留存在本地（`http://pandaspool.local`），无公网暴露，极大的降低了安全与运维门槛。

## 2. 硬件契约与 Hub 推荐清单

为了保证项目的开源普适性，取消“Newifi D2 作为唯一推荐”的限制，确立以下分级硬件支持标准（要求支持 arm64/amd64，最低 512MB RAM）：

| 定位 | 推荐机型 | 配置 | 理由与适用场景 |
|---|---|---|---|
| **公开参考机型 (Reference)** | **香橙派 Orange Pi Zero 3** | 四核 A53, **2GB RAM**<br>千兆网口, Wi-Fi 5 | **主推标准件**。性能充裕，完美承担全套 Go 后端、SQLite、MQTT 及多路视频分发。甚至能自建 AP 热点。性价比极高。 |
| **高阶稳定版 (Pro)** | **NanoPi R2S Plus** | 四核 RK3328, 1GB RAM<br>自带 32GB eMMC | eMMC 颗粒寿命远高于 TF 卡，适合对 SQLite 历史数据长久保存有极高要求的专业工作室。 |
| **通用容器版 (Generic)** | 任意 Linux 小主机 / 树莓派 / NAS | x86_64 或 ARM64 | 提供标准的 `docker-compose.yml`，一键部署，适合已有服务器集群的极客。 |
| **遗留/降级版 (Legacy)** | **新路由 3 (Newifi D2)** | MT7621, 512MB RAM<br>32MB 闪存 | **仅做网关和简易状态流转**。无法使用 Docker，无法跑大型分析，仅适合二手极限低成本验证。 |

## 3. 局域网 A1 摄像头拉流重构

完全推翻 Gemini 此前提出的“通过 TUTK 解包并需要外网 HTTPS + Token 鉴权”的弯路。
A1 摄像头的局域网解决方案应极简且安全：

1. **直连解包**：PandaSpool Hub（例如 Orange Pi）在本地网络中，直接通过 TLS 6000 端口，使用 LAN Access Code 连接打印机，提取 JPEG 帧。
2. **多路分发**：Hub 将提取的帧封装为标准的 MJPEG 视频流，通过同源的本地接口（如 `/api/printers/a1/camera`）分发给所有连接到 Hub 的浏览器。
3. **安全闭环**：
   - 浏览器与 Hub 均在 `http://pandaspool.local` 域内，**彻底消灭了 HTTPS 网页加载 HTTP 视频的 Mixed Content 报错**。
   - Access Code 仅保存在 Hub 的本地配置文件中，绝对不向前端暴露。
   - 一个上游连接，多个下游浏览器观看，大幅降低打印机网卡负担。

## 4. 空气传感器节点重构 (Air Nodes)

放弃“一根穿墙线、一个主板带所有外设”的硬核接线方案。为了便于用户复刻、降低排错难度，改为**分离的双节点架构**，并全面转向 **ESPHome** 固件。

### 4.1 固件与软件逻辑调整
- **拥抱 ESPHome**：直接使用 ESPHome 原生组件，项目只提供 `chamber-node.yaml` 和 `room-node.yaml`，用户可一键网页刷入预编译固件。
- **修正传感器语义**：SGP41 在 UI 中仅显示无量纲的 `VOC Index` / `NOx Index` 及排放事件趋势图，**不再显示浓度或毒性绝对值**。
- **动态采样延长寿命**：PMS5003 激光器寿命有限（约 8000 小时）。通过软件配置：打印空闲时降频（2-5 分钟/次），打印中高频（10-30 秒/次），以此大幅延长寿命。

### 4.2 模块 A：仓内部件 (Chamber Air Node)
| 模块 | 精确型号 | 状态 | 作用 |
|---|---|---|---|
| **主控** | **ESP32-C3 SuperMini** | 必需 | 仅负责封箱内部的数据采集。 |
| **仓内温度/湿度** | **SHT40 / SHT30** | 必需 | 监测仓温是否达标，并为 SGP41 提供湿度补偿。 |
| **仓内气体趋势** | **SGP41** | 推荐 | 捕捉 ABS/劣化耗材的特征挥发峰值。 |
| **仓内漏粉监控** | **PMS5003** | 可选 | 监控耗材受潮拉丝、齿轮磨损导致的粉尘暴增。 |
| **耗材重量称量** | **HX711 放大器 + 3kg平行梁称重传感器** | 扩展 | 放置于料盘底部，精确计算剩余耗材余量（空盘去皮），彻底解决余量焦虑。 |


### 4.3 模块 B：房间对照部件 (Room Air Node)
| 模块 | 精确型号 | 状态 | 作用 |
|---|---|---|---|
| **主控** | **ESP32-C3 SuperMini** | 必需 | 独立部署于车间墙壁或桌面，免去复杂穿墙布线。 |
| **室内温湿度** | **SHT40 / SHT30** | 必需 | 房间基准参考。 |
| **人体联动** | **LD2410C (毫米波)** | 可选 | 侦测人进入车间，触发更高强度的净化排风。 |
| **室内空气** | **PMS5003** | 二期扩展 | 验证封箱过滤系统是否失效（对比仓内数值）。 |

## 5. 迭代顺序规划 (Roadmap)

项目推进应遵循“先核心自洽，再边缘拓展”的逻辑：

- **P0 独立 Hub 闭环**：验证 Orange Pi 启动 Web 页面、局域网配对 A1、拉取状态与 6000 端口摄像头分发。（拔掉网线，系统仍需正常运作）。
- **P1 Profile 引擎**：落实“机器→喷嘴→材料→用途”的核心工艺参数生成，脱离对云端 AI API 的强依赖，改用本地结构化规则树兜底。
- **P2 Chamber Node**：跑通 ESPHome 仓内节点采集，在网页渲染 24h 完整的打印过程环境曲线。
- **P3 Room Node 与自动化 (P4)**：接入环境对照节点，完成插座启停与联动逻辑（如打印后延时散味、有人进屋加强净化）。
- **P5 远程访问**：最后才提供基于 Tailscale / WireGuard 的局域网外连可选模块。
